## A. Damage — where the final damage is computed

**Verified answer**

- All agent hits — melee (`Mission.MeleeHitCallback`), missiles (`MissileHitCallback`),
  area damage (`MissileAreaDamageCallback`), horse charge (`ChargeDamageCallback`), fall
  (`FallDamageCallback`) — go through one private method,
  `Mission.GetAttackCollisionResults` (`TaleWorlds.MountAndBlade\…\Mission.cs` ~6541).
- It first calls `MissionCombatMechanicsHelper.GetAttackCollisionResults`, whose
  `ComputeBlowDamage` applies armor (`StrikeMagnitudeModel.ComputeRawDamage` with
  `CalculateAdjustedArmorForBlow`), bone multiplier, sneak attack and difficulty →
  `attackCollisionData.InflictedDamage` (clamped 0–2000). Shield-blocked hits go through
  `ComputeBlowDamageOnShield` instead.
- Then, only if that damage is > 0:
  `MissionGameModels.Current.AgentApplyDamageModel.CalculateDamage(...)` and the result is
  written back with `MathF.Round(...)`. After that, knockdown/stagger/dismount/shrug-off
  decisions (`MissionCombatMechanicsHelper.Decide*`) read the new `InflictedDamage`.
- `AgentApplyDamageModel.CalculateDamage` (`…ComponentInterfaces\AgentApplyDamageModel.cs`)
  is **non-virtual**: `IsDamageIgnored` → `ApplyDamageAmplifications` → `ApplyDamageScaling`
  → `ApplyDamageReductions` → **`ApplyGeneralDamageModifiers`** → `Max(0, …)`, each called on
  `MissionGameModels.Current.AgentApplyDamageModel` (i.e. on the top model = us).
- **Decoration works in v1.4.8.** `MBGameModel<T>` (`TaleWorlds.Core\MBGameModel.cs`) has
  `protected T BaseModel`; both `CampaignGameStarter.AddModel<T>` and
  `BasicGameStarter.AddModel<T>` call `GetModel<T>()` (last registered) and
  `gameModel.Initialize(previous)`. `MissionGameModels` picks the LAST registered model of
  each type (`GameModelsManager.GetGameModel<T>`).
- Registration order: campaign → `SandBoxSubModule.OnGameStart` adds
  `SandboxAgentApplyDamageModel`; War Sails adds `NavalAgentApplyDamageModel` (itself a
  decorator); custom battle → `CustomGame.InitializeGameModels` adds
  `CustomAgentApplyDamageModel` BEFORE `GameManager.OnGameStart`; naval custom battle →
  `NavalCustomGame` adds `NavalDLCCustomAgentApplyDamageModel`. `MBGameManager.OnGameStart`
  calls every submodule's `OnGameStart(game, starter)` and only then builds
  `MissionGameModels` from `starter.Models`. So one registration in our `OnGameStart` covers
  all three game types.

**Recommended approach**

```csharp
// Module/Models/TraxDamageModel.cs — decorator, NOT a Default*/Sandbox* subclass
public sealed class TraxDamageModel : AgentApplyDamageModel
{
    public override float ApplyGeneralDamageModifiers(in AttackInformation ai, in AttackCollisionData cd, float dmg)
    {
        float d = BaseModel.ApplyGeneralDamageModifiers(in ai, in cd, dmg);
        try
        {
            if (d <= 0f || !cd.IsColliderAgent || ai.IsVictimAgentNull
                || cd.AttackBlockedWithShield || cd.IsFallDamage) return d;
            // cfg read AT USE TIME (hot swap): enabled, percent, melee/ranged, mounts
            // ranged = cd.IsMissile; mount victim = ai.IsVictimAgentMount;
            // horse-charge = cd.IsHorseCharge (treat as melee)
            return DamageRoll.Apply(d, factor);   // Core: d * U[1-p, 1+p], never below 1 if d > 0
        }
        catch (Exception e) { Log.Error("[damage]", e); return d; }   // fail safe = vanilla
    }
    // EVERY other abstract member: => BaseModel.Same(...)  (IsDamageIgnored, ApplyDamage*,
    // DecideMissileWeaponFlags, CalculateShieldDamage, CalculateSailFireDamage, … ~30 members)
}

// SubModule.OnGameStart(Game game, IGameStarter starter):
if (starter.Models.Any(m => m is AgentApplyDamageModel))
    starter.AddModel<AgentApplyDamageModel>(new TraxDamageModel());
```

- The `Models.Any` guard skips game types without a damage model (no null `BaseModel`).
- "Never rounds below 1": the game does `MathF.Round(result)`, so return `Max(1f, d * f)`.
- RNG: use a thread-safe generator (`[ThreadStatic] Random` in Core). Thread (step 4, read
  in source): `MeleeHitCallback`, `MissileHitCallback`, `MissileAreaDamageCallback`,
  `ChargeDamageCallback`, `FallDamageCallback` are all `[MBCallback(null, false)]` —
  `isMultiThreadCallable: false` (`MBCallback.cs`), unlike e.g. `OnFixedTick` /
  `GetDefendCollisionResults` (`true`) — so damage runs on the **main thread**. The in-game
  `[damage] first roll this mission - on the main thread` line confirms it (PLAYTEST §2a).
- The combat log / "report damage" line shows the rolled number (`combatLog.ModifiedDamage`)
  — a free visual check.

**Risks / open points**

- SubModule.xml: `NavalDLC` as `LoadBeforeThis optional="true"` so we wrap the DLC's model
  (TrainingBattles pattern). Functionally either order works (both delegate).
- RBM (installed on Anton's machine) Harmony-patches combat; compatibility **UNVERIFIED**.
- Implication 2 (knockdown etc. follow the rolled damage) and 3/4 (what is excluded).

## B. Detecting a blow — released and landed

**Verified answer**

- **Ranged release**: `Mission.OnAgentShootMissile` (Mission.cs ~4951) is called by the
  engine for every shot/throw, AI and player, and forwards to
  `MissionBehavior.OnAgentShootMissile(shooterAgent, weaponIndex, position, velocity,
  orientation, hasRigidBody, forcedMissileIndex)` for every behavior. Crossbow = fires on
  the shot (the reload is separate). Siege engines use other paths — they never fire it.
  The engine passes `isPrimaryWeaponShot` but behaviors do not get it: a multi-projectile
  weapon could fire the event more than once per release → dedupe per agent (ignore a
  second shot within ~0.1 s).
- **Melee release: no event.** The only engine callbacks are listed in Mission.cs /
  Agent.cs (`MBCallback`); none marks a swing. `Agent.LastMeleeAttackTime` is only updated
  on a registered HIT (`Agent.UpdateLastAttackAndHitTimes`), not a swing. So: poll
  `agent.GetCurrentActionType(1)` (channel 1 = upper body; vanilla reads attacks there, e.g.
  `Agent.HandleDropWeapon`, `HumanAIComponent.IsInImportantCombatAction`) and count the
  rising edge into `Agent.ActionCodeType.ReleaseMelee` (20). Kicks (`Kick` 28) and shield
  bashes (`WeaponBash` 31) are different codes. Alternative signal:
  `GetCurrentActionStage(1) == Agent.ActionStage.AttackRelease`.
- Cost precedent: vanilla itself polls `GetCurrentActionStage(1)` for every agent —
  `CustomBattleAutoBlockModel` (all humans, per call) and `Agent.TickParallel` (per agent per
  frame, multiplayer). Both are native calls (`MBAPI.IMBAgent`).
- **Landed**: `MissionBehavior.OnMeleeHit(attacker, victim, isCanceled, collisionData)`
  fires once per melee collision — flesh, shield block (`collisionData.AttackBlockedWithShield`),
  parry/block/chamber (`CollisionResult` Parried/Blocked/ChamberBlocked) and object hits.
  A swing that passes through several targets fires it several times → dedupe per swing.
  `MissionBehavior.OnMissileHit(attacker, victim, isCanceled, collisionData)` for missiles.
  `OnAgentHit` / `OnRegisterBlow` / `OnScoreHit` fire only for REGISTERED blows (not for
  blocks/parries) — do not use them for "landed incl. shield".
- Couched lance / braced spear: `attacker.IsDoingPassiveAttack` in `OnMeleeHit`
  (Mission.cs ~5367); there is no release action to poll.

**Recommended approach**

- One `EnduranceLogic : MissionLogic`. Per tracked human agent keep `lastActionType`.
  Each mission tick, for each active tracked agent:
  `var t = a.GetCurrentActionType(1); if (t == ReleaseMelee && prev != ReleaseMelee) Charge(a); prev = t;`
  — flat array loop, no allocations.
- `OnAgentShootMissile` → `Charge(shooter)` (with the 0.1 s dedupe).
- `CostOnMiss == false`: charge from `OnMeleeHit` (first hit of a swing only — key on the
  attacker's swing counter) and `OnMissileHit` with a victim agent, instead of the release.
- Couched/braced hits: `OnMeleeHit` with `attacker.IsDoingPassiveAttack` → one blow
  (implication 5).
- If per-frame polling of ~1000 agents shows up in profiling, move the poll into an
  `AgentComponent.OnTickParallel` (runs on worker threads via `TWParallel.For`,
  `Mission.TickAgentsAndTeamsImp`; vanilla reads the action stage there too) writing only
  the component's own fields, and apply consequences on the main thread.

**Risks / open points**

- **UNVERIFIED**: that every mounted swing shows up as `ReleaseMelee` on channel 1, and how
  long the release phase lasts for the fastest weapons (sets how sparse the poll may get).
  Step 5: log per-agent blow counts with `VerboseLogging` and compare with what is seen.
- Held attacks (hold-to-ready) cost only on release — correct per DESIGN.

## C. Slowing attacks to 20%

**Verified answer**

- Driven properties (`TaleWorlds.Core\DrivenProperty.cs`): `SwingSpeedMultiplier` (66),
  `ThrustOrRangedReadySpeedMultiplier` (67 — thrusts, bow draw, throw), `HandlingMultiplier`
  (68), `ReloadSpeed` (69 — crossbow), `BipedalRangedReadySpeedMultiplier` (95),
  `BipedalRangedReloadSpeedMultiplier` (96).
- Computed by `AgentStatCalculateModel.UpdateAgentStats(agent, props)`; sandbox:
  `SandboxAgentStatCalculateModel.SetWeaponSkillEffectsOnAgent` (swing/thrust/reload from
  weapon skill), `SetMountedPenaltiesOnAgent`; custom battle:
  `CustomBattleAgentStatCalculateModel` (`SwingSpeedMultiplier = 0.93 + 0.0007 × skill`,
  thrust = swing). Throwing speed feeds `ThrustOrRangedReadySpeedMultiplier`. The two
  `Bipedal*` values are global managed parameters (`ManagedParametersEnum` 7/8), not skill.
- Recompute path: `Agent.UpdateAgentProperties()` (public) →
  `AgentDrivenProperties.UpdateDrivenProperties(agent)` →
  `MissionGameModels.Current.AgentStatCalculateModel.UpdateAgentStats(agent, this)` → native
  `UpdateDrivenProperties`. The game calls it on weapon wield/usage change, mount,
  dismount, amount change, etc. (Agent.cs — ~15 call sites). So a DECORATOR's change is
  re-applied by every recompute.
- Clamp: managed code only clamps with `Math.Max(0f, …)` (mounted penalties). **UNVERIFIED**
  whether the native side clamps a 0.2 multiplier — must be measured in game (step 5).
- War Sails' `NavalAgentStatCalculateModel.UpdateAgentStats` calls `BaseModel` first and
  then only touches naval stats / `HandlingMultiplier` — no conflict.

**Recommended approach**

```csharp
public sealed class TraxAgentStatModel : AgentStatCalculateModel   // decorator
{
    public override void UpdateAgentStats(Agent agent, AgentDrivenProperties p)
    {
        ForwardAiLevel();                        // see risk below
        BaseModel.UpdateAgentStats(agent, p);
        try
        {
            if (agent.IsHuman && Endurance.IsExhausted(agent))   // live config read
            {
                float f = cfg.ExhaustedAttackSpeedPercent / 100f;
                p.SwingSpeedMultiplier *= f;
                p.ThrustOrRangedReadySpeedMultiplier *= f;
                p.ReloadSpeed *= f;
            }
        }
        catch (Exception e) { Log.Error("[speed]", e); }
    }
    // every other abstract/virtual member => BaseModel.Same(...)
}
```

- Flip: when an agent enters/leaves exhaustion, set its flag and call
  `agent.UpdateAgentProperties()` once (main thread). Only transitions — never per tick.
- Do NOT scale the `Bipedal*` globals unless the step-5 measurement shows bows/crossbows
  are not slowed (their exact engine meaning is **UNVERIFIED**; scaling both could square
  the penalty). Leave `HandlingMultiplier` alone (defence/handling, not attack speed).

**Risks / open points**

- **Tournament quirk**: `TournamentBehavior` calls
  `MissionGameModels.Current.AgentStatCalculateModel.SetAILevelMultiplier(...)` — a
  NON-virtual method writing a private field `_AILevelMultiplier` of the TOP model, while the
  base model's `SetAiRelatedProperties` reads its OWN field. Any decorator (War Sails' too —
  vanilla already has this bug with the DLC) swallows tournament AI scaling. Fix: before
  delegating, read our own `_AILevelMultiplier` (cached reflection / compiled getter) and, if
  changed, call `SetAILevelMultiplier(value)` on every `AgentStatCalculateModel` in
  `MissionGameModels.Current.GetGameModels()`.
- Every other public member must be forwarded, including virtual ones with a base body
  (`GetEffectiveMaxHealth`, `GetEnvironmentSpeedFactor`, `GetEffectiveSkill`,
  `InitializeMissionEquipment*`, …) — otherwise the base class's default silently replaces
  the sandbox logic.

**Step 5c addendum — run speed, horse speed, wounds, the skill (verified in source, 2026-09-27)**

- **Run speed on foot = `MaxSpeedMultiplier` (87)**. Sandbox's `UpdateHumanStats` assigns it
  with `=`: `GetEnvironmentSpeedFactor × clamp(0.7 × (1 + 0.001 × Athletics) − 0.2 × (1 −
  0.001 × Athletics) × load ÷ 80, 0, max at skill 300)` (SandboxAgentStatCalculateModel.cs
  ~1069-1082; `DefaultSkillEffects.AthleticsSpeedFactor` is +0.1% per point), then again
  after perks (~1580). CustomBattle's model likewise (~324, ~412); War Sails multiplies inside
  its own BaseModel-first pass. So our scaling after the base never compounds.
- `CombatMaxSpeedMultiplier` (88) = min(lerp(`BipedalCombatSpeedMinMultiplier` 0.74,
  `…Max` 0.84, load ÷ weight), 1) — a share of the top speed kept in combat stance; left
  alone (scaling it too would square the run penalty while fighting).
- **Horse speed = `MountSpeed` (93)** on the MOUNT agent's own properties: `UpdateHorseStats`
  assigns `environment × 0.22 × (1 + speed)` with `=` (reading its rider's Riding skill). A
  rider mounting recomputes only the rider (`Agent.OnMount` → `UpdateAgentStats`, Agent.cs
  ~1749) — so a slowed horse is recomputed by us; our decorator finds it through the logic's
  own table (horse index → rider record, reference-checked), no native call.
- **Wounds**: `MissionBehavior.OnAgentHit` fires after `Health` is lowered (Agent.cs ~5467 →
  `Mission.OnAgentHit` ~5628). `Agent.Health` (`_health`) and `HealthLimit` are managed.
- **Horse charges**: `AttackInformation.AttackerAgent` is the MOUNT (`IsAttackerAgentMount`);
  the rider is its `RiderAgent`.
- **The Athletics skill**: `agent.Character.GetSkillValue(DefaultSkills.Athletics)` —
  `CharacterObject` asks its `HeroObject` for heroes (CharacterObject.cs ~792), troops read
  their XML skills. v1.4.8 data: imperial recruit 20, infantryman 40, elite cataphract 60,
  legionary 130, Fian champion 170 (SandBoxCore spnpccharacters.xml, used by custom battle
  too); custom-battle commanders 80–90 (`custombattle_commander_*` skill sets).
- **UNVERIFIED** (step 5c's summary settles each): the engine honours a changed
  `MaxSpeedMultiplier` / `MountSpeed` mid-mission, and `GetMaximumForwardUnlimitedSpeed()`
  follows it (`run speed check … engine top x… asked x…`).

**Step 5e addendum — the whole attack cycle (verified in source and data, 2026-09-27; detail in
AI_NOTES "Step 5e")**

- **Channel 1 phases**: `ReadyMelee` (19) wind-up + held → `ReleaseMelee` (20) swing +
  follow-through → `BlockedMelee` (22, the attacker's recoil after a block or parry;
  `ParriedMelee` 21 is only couched-lance / braced-spear) → the pause → the next ready (a chain
  goes Release → Ready). Ranged: `ReadyRanged` (15) draw + aim → `ReleaseRanged` (16) /
  `ReleaseThrowing` (17) → `Reload` (18: bow nock, crossbow wind, the next javelin).
- **Which property scales which phase**: swing / thrust-or-ranged-ready = the ready AND the
  release (native `ready_speed_multiplier` 2.2 / `release_speed_multiplier` 1.2 act on top);
  `ReloadSpeed` = the reload; `HandlingMultiplier` = handling, i.e. the DEFENCE side (native
  `defend_speed_multiplier` 3.2) - never touched; the block recoil has no visible property
  (`added_animation_duration_for_blocked_attacks` 0.095 s is added natively); no property sets
  the time between attacks.
- **Per-agent action speed is not safe**: `Agent.SetCurrentActionSpeed(channel, speed)` sets an
  ABSOLUTE speed with no getter, vanilla uses it only on siege-machine usage animations, and the
  native combat code paces attack actions itself (the on-hit slow-down every frame). Not built.
- **The AI's pause**: `SetAiRelatedProperties` assigns every Ai* value with `=` on every recompute
  - `AIAttackOnDecideChance` (the chance to attack at a decision; vanilla lowers it for defensive
  orders), `AIAttackOnParryChance` (riposte), `AiShootFreq`, `AiWaitBeforeShootFactor` (0 for siege
  defenders with an ammo supply). The first three × m, the last ÷ m, in the stat decorator.
- **A hold**: `SetScriptedFlags(GetScriptedFlags() | NoAttack)` with no scripted position is
  vanilla's own "do not attack" (`Agent.UseGameObject`); the flag word is shared with scripted
  jobs, so it is set only on a free man and lifted only while he is free.

**Step 13 addendum — holding the PLAYER's attacks (verified in source 2026-09-27; detail and every

## D. Movement — standing or moving

**Verified answer**

- `Agent.MovementVelocity` (Vec2, local frame, native `GetMovementVelocity`),
  `Agent.GetCurrentVelocity()` (Vec2), `Agent.Velocity` (Vec3, rotated to world),
  `Agent.AverageVelocity` (Vec3). Vanilla precedents: one check treats
  `GetCurrentVelocity().LengthSquared < 0.25f` (0.5 m/s — our default threshold) as still
  (Agent.cs ~3209); `AgentPathNavMeshChecker` treats `MovementVelocity.LengthSquared > 0.01f`
  as moving.
- Rider → `agent.MountAgent` (null on foot).

**Recommended approach**

- `var m = agent.MountAgent ?? agent; bool moving = m.MovementVelocity.LengthSquared > t*t;`
  with `t = MovingSpeedThreshold`. Sample at the regen rate (e.g. every 0.25 s per agent),
  not every frame.
- Regeneration is a pure Core function of (seconds since last blow, dt, moving) → unit-test it.

**Risks / open points**

- **UNVERIFIED** that a rider's own `MovementVelocity` follows the horse — using the mount's
  avoids the question.

**Step 5c addendum — walk vs run (regen by effort; verified in source and data, 2026-09-27)**

- The game has two gaits of its own. **Walk** = `Agent.WalkSpeedCached` = the mount's
  `WalkingSpeedLimitOfMountable` (native) or `Monster.WalkingSpeedLimit` (Agent.cs ~3732):
  `monsters.xml` human **1.8 m/s** (settlement 1.6 / 1.4, child 1.6). A formation told to walk
  moves at the MIN `WalkSpeedCached` of its men × the walk restriction; one told to run at the
  AVERAGE `GetMaximumForwardUnlimitedSpeed()` (Formation.cs ~1338 / ~1357). **Run** =
  `GetMaximumForwardUnlimitedSpeed()`, native.
- The run speed itself is computed natively. `native_parameters.xml` has
  `bipedal_speed_multiplier` 6.2 (and `bipedal_sprint_speed_ratio` 0.37); with
  `MaxSpeedMultiplier` ≈ 0.63–0.79 for typical troops (skill 20–130, 15–35 kg carried), a top
  of 6.2 × that = 3.9–4.9 m/s → **walk ÷ top ≈ 0.37–0.46, about 0.42**. That product is an
  INFERENCE (the native formula is not visible).
- Decision (step 5c): `WalkEffortFraction` stays **0.4**. Above it the rate falls in a straight
  line, so a walk measured at 0.42 still refills at 98% of the full rate — the exact edge
  barely matters. The summary's `walk vs run speeds (tune WalkEffortFraction …)` line
  measures walk ÷ top in every mission (walk limit and top of every fresh fighter at
  deployment); if it comes out well above 0.4, move the default to it.

**Step 6 addendum — binding, prefabs, layers (verified in source 2026-09-27; decompiled
`TaleWorlds.GauntletUI.Data` and `.ExtraWidgets` beside the others)**

- **Binding converts only strings.** `GauntletView` → `WidgetExtensions.SetWidgetAttribute`
  (PrefabSystem) finds the widget property by reflection (a dotted name like `Brush.FontColor`
  walks getters, only the last part needs a setter) and `ConvertObject` turns a STRING into a
  Sprite, Brush, int or Color; anything else is handed over as it is. So a ViewModel property
  must have exactly the widget property's type: `float` for `SuggestedWidth`, `Margin*`,
  `PositionXOffset`, `ScaledPositionXOffset`, `AlphaFactor`, `InitialAmountAsFloat`;
  `TaleWorlds.Library.Color` for `Color` and `Brush.FontColor`; `bool` for `IsVisible`. Vanilla
  does each: `SingleplayerKillfeed.xml` `Color="@BackgroundColor"` (a Color property),
  `GamepadCursor.xml` `ScaledPositionXOffset="@CursorPositionX"` (float - good news for
  UNVERIFIED #7), many `Brush.FontColor="@…"` and `FillBarWidget InitialAmountAsFloat="@…"`; the
  sibling ImmersiveAI binds `MarginTop="@…"` from a float. `ViewModel` has typed
  `OnPropertyChangedWithValue` overloads (bool, int, float, uint, Color, double, Vec2, class) and
  `GauntletView` listens to all of them; any property is bindable (`[DataSourceProperty]` optional).
- **Unknown attribute names are silently ignored** (`GetObjectAndProperty` returns null): a typo
  never errors in game. Static strings parse as int / float (invariant) / bool (`"true"`) /
  string / enum / `#RRGGBBAA` Color / a Brush or Sprite by name / a Widget by child-Id path.
- `BrushWidget.Brush` hands out a per-widget CLONE on first get: `Brush.FontColor` changes this
  text only. Put `Brush="…"` before `Brush.FontSize` / `Brush.FontColor` in the XML.
- **`FillBarWidget`** (ExtraWidgets): in `OnLateUpdate` sets its `FillWidget`'s
  `ScaledSuggestedWidth` = clamp(Initial / Max, 0..1) × (its own width − the fill's margins) - a
  share of the bar, no pixel maths, the UI scale for free. Late update is picked up by type
  (`WidgetInfo.GotCustomLateUpdate`).
- **Prefabs**: every enabled module's `GUI\Prefabs\*.xml` is registered at startup by FILE NAME
  (`WidgetFactory.Initialize`; the same name in two modules asserts and the later wins - so ours

  `WidgetPrefab.LoadFrom` reads with `IgnoreComments` and takes `Prefab/Window`'s FIRST child as
  the root. `GauntletLayer.LoadMovie` tries the generated-prefab context (null for a mod), then
  `GauntletMovie.LoadMovie`; a missing prefab gives a movie with no `RootWidget`.
- **Removing a layer**: `ReleaseMovie` first, then `ScreenBase.RemoveLayer` (→ `HandleFinalize` →
  `ClearContext` releases every movie still held; `OnFinalize` asserts on a loaded one). A movie
  that never loaded THROWS when released (`GauntletMovie.Release` → `_moviePrefab` null) - so a
  failed layer must never be added to the screen.
- **View hooks**: `OnMissionScreenTick` (vanilla skips `MBCommon.IsPaused` frames),

  `OnMissionTick` is safe (the view ticks from the next frame).
- **Hide Battle UI** = `BannerlordConfig.HideBattleUI`, an Options → Gameplay checkbox (SP only).
- **Where the vanilla bars sit** (sprite sizes from `NativeSpriteData.xml`): hero frame

### R1. The hit pipeline - who decides what, and when

1. **A melee collision** reaches managed code as `Mission.MeleeHitCallback` (Mission.cs 5297, `[MBCallback(null, false)]` -
   the main thread, step 4). `flag` = the collision is Parried / Blocked / ChamberBlocked (5300) - a SHIELD block is
   `Blocked` too. `flag2` (cancel damage) = … || (flag && !AttackBlockedWithShield) (5313): a WEAPON parry is cancelled
   (its `InflictedDamage`, `BaseMagnitude` zeroed, 5358-5364), a shield block is not (the shield takes the damage).
2. **The blow is built for EVERY collision**, blocked or not: `CreateMeleeBlow` (5367 → 5496). It sets `AttackType` Kick
   (no weapon) / Bash / Standard (5501-5508), `DamageType` Blunt for kicks and bashes (5512), copies
   `AttackerStunPeriod` / `DefenderStunPeriod` from the collision data (5514-5515), then asks the damage model, in this
   order (5553-5583): `DecideAgentShrugOffBlow` → `ShrugOff`; a rider → `DecideAgentDismountedByBlow` → `CanDismount`; on foot
   → `DecideAgentKnockedBackByBlow` → `KnockBack`, `DecideAgentKnockedDownByBlow` → `KnockDown`; a horse →
   `DecideMountRearedByBlow` → `MakesRear`.
3. **But a BLOCKED blow is never registered**: `RegisterBlow` runs only `if (!flag && …)` (5368-5371). So the `Decide*`
   answers for a blocked or parried blow are computed and THROWN AWAY - **no knockdown, knockback or dismount can come from
   a blocked blow through the model.** (A blocked blow reaches the behaviours as `OnAgentHitBlocked` → `OnAgentHit(isBlocked:
   true)` with a 0-damage blow, 5480-5493, and as `OnMeleeHit`, 5381-5384 - after the fact.)
4. **A registered blow** goes `RegisterBlow` (5412) → `victim.RegisterBlow` (5437) → `Agent.HandleBlow` (Agent.cs 5413):
   sound, then **`if (b.InflictedDamage <= 0) return;` (5438) - a 0-damage blow plays NO reaction at all** - health,
   `Mission.OnAgentHit` → every behaviour's `OnAgentHit` + `OnScoreHit` (5468 → Mission.cs 5612-5616, `in Blow` - read only),
   death, and LAST `HandleBlowAux(ref b)` (5475) = native `IMBAgent.HandleBlowAux`: the engine plays the reaction from the
   blow's flags and stun periods (UNVERIFIED in detail - native). `OnRegisterBlow` (Mission.cs 5452) comes after it, the blow
   by value. **So no behaviour callback can change a landed blow before the engine reacts** - the model's `Decide*` (inside
   `CreateMeleeBlow`) is the only managed place, and only for landed blows.
5. **Kicks and bashes** (`IsAlternativeAttack`): `DecideAgentKnockedBackByBlow` returns TRUE for every one (MCMH 60-63) -
   every landed kick or bash knocks back in vanilla. `DecideAgentKnockedDownByBlow` is passed `attackerWeapon.CurrentUsageItem`
   (Mission.cs 5575), which is null for a kick (`MissionWeapon.Invalid`, MissionWeapon.cs 43 / 136) → MCMH 88 skips it: **a
   kick never knocks down in vanilla**; a bash passes the shield, whose `CanWeaponKnockDown` needs `WeaponFlags.CanKnockDown`
   (CustomAgentApplyDamageModel.cs 189-214) - shields lack it. A kick's damage is `CalculateAlternativeAttackDamage` (1-2,
   CustomAgentApplyDamageModel.cs 263-282) as its base magnitude (MCMH 625-631), then armour - a kick rounding to 0 never
   reacts (point 4).
6. **Horse charges** (`ChargeDamageCallback`, Mission.cs 6034-6066): `DecideAgentKnockedBackByBlow` / `…KnockedDownByBlow`
   with a null weapon, registered only when damage > 0.

  (3314), `IsUsingGameObject` (668), `Health` / `HealthLimit`.

### R8. The player, riders, horses

- **The player** is an `Agent` like any: the decorators' `Decide*` and stun multipliers apply to him as attacker and as victim;
  `SetActionChannel` / `DropItem` work on the main agent (vanilla's drop key is his). Whether his input is ignored during a
  strike action is native (UNVERIFIED - in vanilla he cannot block while flinching). RBM gives a first-person player no
  stagger clip (it looks awful in first person) and blocks his input instead (Visuals.cs 196-216) - a hint for us: the forced
  ANIMATION may be wrong for the first-person camera; the stun multipliers are fine.
- **Riders**: on a horse, `CreateMeleeBlow` asks `DecideAgentDismountedByBlow` instead of knockback / knockdown (5561-5568) -
  "knocked down" = knocked off. Never a forced stagger on a rider's channel 0 (the horse's legs) - RBM uses channel 1 when
  mounted.
- **Horses**: `MakesRear` only (5581); a horse charge knocks men back / down through the same two `Decide*` (6053-6063).

### R10. The spike (step 47) - how each lever is pulled and measured (verified in the v1.4.8 decompile 2026-10-17; the engine's answer = PLAYTEST D16)

1. **Where the decorator's two methods sit** (Mission.cs 5296-5420, `MeleeHitCallback`, main thread): `CreateMeleeBlow` runs for EVERY
   collision, blocked or not (5367), and asks `DecideAgentKnockedDownByBlow` only `if (collisionData.IsColliderAgent)` on a man on foot
   (5553-5577); then `RegisterBlow` only `if (!flag && victim active)` (5368) - so the spike answers KnockDown only for a collision the
   engine will register: an alternative attack (`IsAlternativeAttack`), `CollisionResult == StrikeAgent` (1), not `AttackBlockedWithShield`
   (Core `SpikeMath.KickLanded`). The behaviours' `OnMeleeHit` runs right AFTER, in the same callback (5381-5384) - the spike's rotation
   peeks the next kick's number in the decorator and `OnMeleeHit` counts it, so both sides agree with no shared state. A kick that hits
   an ARM is turned into `ContinueChecking` before any of this (5301-5303) - neither runs. `OnMeleeHit`'s `collisionData.InflictedDamage`
   is the final one (the blow copies it, 5537) - 0 = no reaction at all (Agent.cs 5438), counted apart.
2. **The stun** (`MCMH.GetDefendCollisionResults` 228-312): our multipliers come AFTER the base model (Sandbox's MightyBlow kept) and
   BEFORE the cap `StunPeriodMax` (`ManagedParameters.Instance.GetManagedParameter`, 308-310). `ManagedParameters` is one static managed
   float array (`TaleWorlds.Core\ManagedParameters.cs` 11-23: `GetParameter` / `SetParameter` public static) - raising the cap is a plain
   write the smoke can check; it is GLOBAL, so the spike remembers the game's value once, restores it at the switch-off / mission end /
   OnRemoveBehavior, and clamps every stun nobody lengthened to it meanwhile (`ImpactHooks.AfterDefendedBlowStun`). The A/B split is by
   the BLOCKER's agent index (even = x3): `Agent.Index` is a managed auto-property, safe on a worker thread.
3. **The channel reads**: `GetCurrentActionType(ch)` is native (`MBAPI.IMBAgent`), `GetCurrentAction(ch).Index` a pointer read
   (`AgentHelper.GetChannel0/1CurrentActionIndex`, Agent.cs 2748-2756) - the watch reads both channels' type + index each tick for the
   ≤ 64 men it watches (never the whole army). The defender of a block has no "defend hit" action TYPE (action_types.xml has none) - his
   guard freeze is measured as "his channel-1 defend action, from the block until its index changes"; the attacker's recoil is
   `BlockedMelee` (22) / `ParriedMelee` (21) on channel 1 (`act_blocked_*` / `act_*_parried` in action_types.xml).
4. **The stagger**: `ActionIndexCache.act_stagger_backward` (ActionIndexCache.cs 161) - its static constructor resolves every name through
   `MBAnimation.GetActionCodeWithName` (native, 439-449), so the offline smoke reads the FIELDS by reflection only; `SetActionChannel(0,
   in act, ignorePriority, 0, 0f, speed)` returns whether the engine took it (Agent.cs 2368-2372). The spike alternates `ignorePriority`
   (false, true, …) - which one the engine needs mid-fight is unknown (UNVERIFIED 27).
5. **The drop**: `Mission.AddTickAction(MissionTickAction.DropItem, agent, slot, 0)` (Mission.cs 3778) - the Mission's own tick runs it
   (3662-3666: `if (!item.Equipment[slot].IsEmpty) item.DropItem(slot)` for an ACTIVE agent only); `Agent.DropItem` → native
   `IMBAgent.DropItem` for anything not burning (4508-4526). Not `HandleDropWeapon` - its "not during a release / bash" refusal (4446)
   does not apply to a queued DropItem; a kicked man is in his reaction, not his own swing.
6. **Our blow**: `Agent.RegisterBlow(Blow, in AttackCollisionData)` → private `HandleBlow` (Agent.cs 4668-4671, 5413-5470): the sound (it
   reads `Mission.FindAgentWithIndex(b.OwnerId)` - the attacker, our owner), `InflictedDamage <= 0 → return` (so ≥ 1), health, then
   `Mission.OnAgentHit(..., isBlocked: false, …)` → every behaviour's `OnAgentHit` (ours counts it inside `ImpactHooks.InOwnBlow`), death
   below 1 HP (credited to the owner), and LAST `HandleBlowAux` (native - the reaction from the flags). The recipe is vanilla's drowning
   blow (`MissionTickAction.RegisterDrownBlow`, Mission.cs 3667-3683: `new Blow(index)`, Blunt, the head bone, `BaseMagnitude` 10,
   `FillAsMeleeBlow(null, null, -1, -1)`, `DamageCalculated`, `GetAttackCollisionDataForDebugPurpose(… StrikeAgent …)`) with `KnockDown |
   KnockBack` (0x20 | 0x10, BlowFlags.cs), 1 damage, the direction attacker → victim, owned by the attacker. No damage model is asked
   (no roll, no reduction) - `RegisterBlow` bypasses `CreateMeleeBlow`.
